# 企業別面接対策の作成

## 背景

このユーザーは、企業研究を自分の実績に接続するフレームワークを持っており、Notion「面接対策フレームワーク(汎用テンプレート)」（https://app.notion.com/p/3d6934b1126f805b946dc9c22a065033）に体系化されている。HENNGE・Fact Baseの実際の選考でこの型を使って通過した実績があり、2026/9/19には転職エージェント同行の面接コーチングを受け、「回答の話し方」に関する追加のルール（結論→理由、QAのずれ回避、丸暗記回避、退職理由のメリデメ順、できない理由の言い切り、KGI/KPI逆算法、業界質問の軸への差し戻し）がそのページに追補として統合済み。

**最重要の原則（2026/9/20に確定）**：企業文化・カルチャー・バリューへの言及で「合う」を主張するのは、相手の土俵で戦うことになり説得力に欠ける。文化の一致を語るのは最終手段。まず自分の行動実績と、企業の事業内容・商材・課題の具体的な接続だけで組み立てる。「文化が合う」を使う場合も、必ず具体的な行動エピソード同士の対応で裏付けられる時だけにする。

## 手順

1. **既存情報の確認**：会社名でNotionを検索する（`notion-search`）。同名のページ（例：FactBase、HENNGE）や、🎯転職ページ内の企業別評価トグルがすでにあれば、まずそれを読んで既存の文脈（スコア、Must/Want判定、過去の対策内容）を把握する。ゼロから作り直さず、既存資産の上に積み増す。

2. **本人側の土台を読む**：
   - 🧭自己理解プロファイル（自己理解の軸・証明欲求・一気通貫の正体）
   - 📄経歴書の下地（全実績・エピソード・数字）
   - 面接対策フレームワーク(汎用テンプレート)（Step0〜5＋追補の話し方の型）
   これらを毎回参照すること。記憶に頼らない。

3. **企業研究（Step1の4種類の情報）**：Web検索・求人票（Google Drive等）で、①事業・商材の課題とベネフィット、②企業理念・ミッション、③求める人物像、④社員の生の声、を集める。求人票のURLがあれば必ず直接開いて確認する。確認できない情報は「未確認」と明記し、推測で埋めない。

4. **Step0（軸）とStep2（実績カード）を選定**：転職の軸のうち、その企業が満たす/満たさない軸を明示する（Must✅⚠️❌の判定含む）。実績カードは、その企業の求める人物像に合うものを選ぶ。

5. **接続（Step3の4視点）**：①価値観の一致ではなく行動の一致で探す、②文化が違う場合は対比で語る、③文化ではなく事業のフェーズで探す、④商材・顧客層への向き合い方で探す。**企業文化への言及は最後の手段。まず①③④を試す。**

6. **回答作成（Step4のテンプレート＋追補の話し方の型を厳守）**：
   - 自己紹介は名前から
   - 全ての回答は結論→理由の順、聞かれたことだけに答える
   - 抽象語（スキル・専門性・文化フィット等）は言語化できる裏付けがある時だけ使う。無ければ平易な自分の言葉に置き換える
   - 退職理由だけはメリット→デメリットの順
   - 「今の会社でできないのか」には、本人の実際の事実（過去に確認した経緯があるならそれ）で言い切る。**裏付けのない理由をそれらしく作文しない**。本人に確認が必要な場合は、そのまま「要事実確認」と明記して本人に確認を求める
   - 成果の再現性はKGI→KPI逆算ロジックで語る
   - 業界質問は職種の大きな軸に戻す

7. **面接官視点での辛口セルフレビュー（省略しない）**：完成した回答一式を、自分がその企業の面接官だったらどう評価するか採点する。少なくとも次の観点を疑う：
   - エピソードと企業の商材・課題が本当に正確に対応しているか（近いだけで微妙にズレていないか）
   - 「言い切っている」事実は本当に本人が確認済みの事実か、それとも都合よく作った仮説か
   - 志望動機・回答が長すぎて「話しすぎ」になっていないか
   - QAのずれがないか
   見つかった懸念点は隠さず本人に提示する。

8. **保存**：その企業のNotionページ（既存なければ「転職」配下の適切な場所に新規作成）に、新しいトグルとして追記する。既存の過去の対策内容は上書きしない。

9. **完了報告**：何を作ったか、面接官視点のセルフレビューで見つかった懸念点を短く報告する。
