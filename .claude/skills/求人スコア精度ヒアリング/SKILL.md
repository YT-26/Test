# 求人スコアリング精度ヒアリング

## 目的

Must/Wantスコアが実際の本人の感覚（気になる／気にならない）とズレていないかを検証し、ズレがあれば理由を具体的に聞き出して、評価軸そのものの精度を上げる。「なんとなく」ではなく、実際のスコア根拠を引用しながら深掘りする。

## 手順

1. `collection://120e5191-69ad-493b-88dc-6d2b30707c89` から `ステータス = '深掘り済み'` の行を全て **rows mode** で取得する（`気になる` チェックの正確な値を読むため、SQLモードではなくrows modeを使う）。

2. ミスマッチを機械的に洗い出す：
   - **高スコア無関心**：Wantスコア≧70 または Must判定=✅、かつ `気になる` = false
   - **低スコア高関心**：Wantスコア<65 または Must判定=⚠️／ステータス=見送り、かつ `気になる` = true

3. ミスマッチが3件未満の場合は、「まだ判断材料が少ないので、もう少し気になるチェックが溜まってから実施しましょう」とだけ伝えて終了する。少ないサンプルで評価基準を変えない。

4. 各ミスマッチ行について、その行の本文（「🎯あなたのビジョンは達成できるか」「懸念点/注意点」の節）を読み、**なぜそのスコアになったかの具体的な根拠**を把握した上で質問を作る。「なんとなく」ではなく、例えば「セラクは軸3（責任の大きさ）を5点にしていましたが、気になるチェックはついていません。何が響かなかったですか？」のように、実際に書いた根拠を引用しながら聞く。

5. `AskUserQuestion` で、1回につき最大4問まとめて聞く。選択肢は「業務内容が具体的にイメージと違った」「年収・勤務地・休日等の見えない条件が引っかかった」「直感的に魅力を感じなかった（言語化できない）」のように選びやすくしつつ、自由記述（その他）も必ず拾う。

6. 回答が集まったら、複数のミスマッチに共通するパターンがないか探す（例：「専門性が特定製品に閉じている会社は高スコアでも興味を持てない」「点数化していない軸——オフィスの雰囲気・企業の伸び方など——が実は効いている」等）。パターンが1件のミスマッチだけから見える場合は、「傾向」と呼べるほどの根拠ではないため、断定せず「まだ1件だけなので仮説程度」と明記する。

7. 見つかった傾向を本人に提示し、📊企業フィット判定フレームワークの重み・ルーブリックを変えるべきかを相談する。**本人の明示的な同意なしに、評価基準（重み・ルーブリック）を絶対に書き換えない。**

8. 変更が合意されたら：
   - 「📊企業フィット判定フレームワーク」ページ（https://app.notion.com/p/3df934b1126f818db0b6ed88d59c4860）を更新する（既存の記述は残しつつ追記・修正。このページ自身に「基準を変えられるのは本人の指示があったときだけ」という運用ルールが明記されているので厳守する）
   - 「求人自動スクリーニング プロンプト履歴(v1バックアップ・変更ログ)」ページに、日付・変更理由・変更前後の内容を追記する
   - Coworkの自動スクリーニングルーティンのプロンプト自体は、Claude Code側から直接書き換えることができない（コネクタ付与の制約で、Coworkのルーティン設定はユーザーが手動でUIから編集する必要がある）。変更後の重み・基準を反映した新しいプロンプト全文を作成し、「これをCoworkのルーティン設定に貼り直してください」と渡す

9. 今回のヒアリングの質問・回答・導いた結論を、🎯転職ページ（https://app.notion.com/p/3df934b1126f81dc8d47ee3743b48d55）に「🔍スコアリング精度レビュー（実施日）」という新しいトグルとして記録する。過去の記録・他の内容は上書きしない。

## 実施頻度についての注意

このヒアリングは「気になる」チェックの蓄積が判断材料になるため、深掘り件数・チェック件数が少ないうちに実行しても意味のある結果は出ない。目安として、深掘り済みかつ気になるチェック済みの行が合計5件以上溜まったタイミング、または本人が「そろそろ精度チェックしよう」と感じたタイミングで実行するのがよい。

**Claude Code側だけでは自動的に定期実行することはできない**（このセッションの組織設定では、Claude Code Remoteのトリガー作成時にMCPコネクタを付与することが禁止されており、Notion連携済みの状態で定期実行するトリガーを自分で作れないため——求人自動スクリーニングのRoutine設定時に確認済みの制約と同じ）。定期的にきっかけが欲しい場合は、Coworkのルーティンで「月イチ程度で気になるチェックが溜まってきたか確認して」という軽いリマインダーだけを設定し（Coworkは既にNotionコネクタを保持しているため設定可能）、実際のヒアリング自体はユーザーがこのSkillを呼び出す形にするのが現実的な運用。
