# 求人候補の深掘り分析

## 背景

Coworkの自動求人スクリーニングルーティンが毎日12:00・18:00に実行され、条件に合いそうな求人を見つけると、Notionのデータベース「🏢 企業候補！（Claude Code連携用）」（https://app.notion.com/p/9b22cdaff38d4564a0ac214e33487d60、data source: `collection://120e5191-69ad-493b-88dc-6d2b30707c89`）に行として追加する。この時点では一次スクリーニング（Must/Wantスコアと事実確認）は済んでいるが、企業レベルの深掘り（企業概要・事業内容・需要動向・本人のビジョンとの適合）はまだされていない。このSkillは、その深掘りを担当する。

データベースのスキーマ：企業名(title) / Must判定(✅・⚠️) / Wantスコア(number) / 年間休日 / 勤務地・転勤 / 年収 / ステータス(未深掘り・深掘り済み・見送り) / 職種 / 掲載日 / 求人URL / 実行日時 / 種別(新規企業・既出企業の別職種) / 確認済み(checkbox) / 気になる(checkbox)。

「気になる」はユーザーが自分で気に入った候補にチェックを入れるための欄（2026/9/20追加、専用ビュー「⭐気になる一覧」あり）。**このSkillが深掘りの過程で勝手にチェックを入れたり外したりしないこと**——「有望」の判定はあくまでこのSkillの完了報告で言葉として伝え、実際にチェックするかどうかはユーザー本人に委ねる。

大元の転職ページは「🎯転職」（https://app.notion.com/p/3df934b1126f81dc8d47ee3743b48d55）。この人の確定している軸・評価基準は同ページの「🧭自己理解・意思決定の軸」および子ページ「🧭自己理解プロファイル」に既にまとまっているので、迷ったらそちらを読んで文脈を掴む。

## 手順

1. `notion-query-data-sources`（rows mode）で、`collection://120e5191-69ad-493b-88dc-6d2b30707c89` から `ステータス = '未深掘り'` の行を全て取得する。0件なら「今は深掘り対象がありません」とだけ報告して終了する。

2. 各行について、Web検索で企業概要・事業内容・需要動向を調べる。求人票のURL（求人URL列）も直接確認し、行に既に入っている年収・勤務地・年間休日等の情報で不足があれば補う。

3. 調べた内容を、その行のページ本文に `notion-update-page`（`insert_content`, position: end）で追記する。**必ずこの見出し構成に従うこと**（このページ全体で統一された型なので、崩さない）：

   ```
   **企業概要**：（設立年・資本金・従業員数・親会社/資本関係など）
   **事業内容**：（何をしている会社か）
   **需要・市場性**：（市場の成長性・需要の裏付け）
   **募集職種**：（給与・休日・残業などポジション固有の情報。行のプロパティに既にある情報は繰り返さず、そこにない詳細を補う）
   **🎯あなたのビジョンは達成できるか**：（下記「評価の軸」を踏まえた適合度の考察。Must判定・Wantスコアと矛盾しないように、なぜそのスコアなのかが伝わる書き方にする）
   **懸念点/注意点**：（リスク、確認できなかった点）
   ```

   種別が「既出企業の別職種」の行は、上記をゼロから書くのではなく、**🎯転職ページで既に評価済みの同じ会社の別ポジションとの違い**（何が同じで何が違うのか、どちらが本人により合うか）を中心に書く。

4. 深掘りが終わったら、その行の `ステータス` プロパティを `notion-update-page`（`update_properties`）で「深掘り済み」に変更する。この会社は明らかに応募対象外だと判断できる場合（経験要件が満たせない、Must✅が絶対に取れない構造など）は「見送り」にし、理由を本文に一言残す。

5. 🎯転職ページの他の部分（既存の20社評価や自己理解セクションなど）は絶対に上書きしない。触るのはこのデータベースの各行だけ。

6. 確認できなかった情報（掲載日・転勤の有無・具体的な残業時間など）は絶対に推測で埋めず「未確認」と明記する。これはこのユーザーが繰り返し強調している運用ルール。

## 評価の軸（このユーザー固有の判断基準）

深掘りの「🎯あなたのビジョンは達成できるか」を書く際は、次の軸に照らして考える（詳細背景は🧭自己理解プロファイル参照）：

- **軸2：一気通貫** — 要件定義〜構築〜運用まで、分業されずに一人で完結して担当できるか。これがMust。
- **軸3：事業への不可欠性** — その会社・製品にとって欠かせないシステムに関わり、責任の大きさを実感できるか。
- **軸4：専門性の資産化** — その仕事を通じて、他社でも通用する専門性が積めるか（会社固有・製品固有すぎて閉じた専門性にならないか、という視点も持つ）。
- **核心の動機（証明欲求）** — 「ヒアリングから成果まで、他人と分割されない自分だけの完結した物語を持てるか」。成果がチームやプロダクト全体に薄まる構造（例：プロダクトマネージャー的な役割）は、スコアが高そうに見えても本人の満足には直結しにくい、という認識を持って書く。

## 完了報告

全ての行を処理し終えたら、以下を短く報告する：
- 処理した件数（新規深掘り／見送り）
- 特に有望な企業があれば名指しで（目安：Wantスコアが🎯転職ページの既存トップ企業＝セラク81点・Fact Base79点に匹敵または上回る、あるいはMust✅かつ高スコア）
- 見送りにした行があれば、その理由も一言
